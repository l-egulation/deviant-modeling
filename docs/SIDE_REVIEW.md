# 달리기 측면·소형 해상도 검토

## 최신: 벌린 기준 자세의 모델 재작업

사용자가 어깨가 고정된 인상을 다시 지적하여 모션 보정에서 변형용 모델 재제작으로 전환했습니다. 후드·얼굴·색감은 유지하고 몸통·소매·하체를 새로 제작하는 방향을 사용자가 선택했습니다. 디자인 원본 `assets/ink-hero.glb`와 기존 달리기 결과는 보존하며, 새 기준 파일은 `outputs/hero-model.blend` / `hero-model.glb`입니다.

- 팔은 수평 T자, 다리는 수직에서 약 23도 벌린 기본 자세입니다. 새 어깨·팔꿈치·손목 및 골반·무릎·발목에 18뼈 리그를 직접 맞췄습니다.
- 후드·얼굴·스카프·장갑·신발은 기존 디자인의 강체 부분을 분리해 사용했습니다. 이전 바지 조각은 신발에서 제거했습니다. 몸통과 소매는 680사각면의 한 연결 메시이며, 각 어깨 구멍의 20개 경계 정점을 소매가 공유합니다. 목·밑단·손목의 의도된 열린 가장자리에 의상 두께를 추가했습니다. 소매 뿌리가 별도 물체처럼 떠 있지 않습니다.
- 팔꿈치·무릎 주변에는 촘촘한 지지 면 고리를 배치했습니다. 처음에는 좁은 가중치 전환 때문에 소매 최대 2.29배, 무릎 최대 3.39배 늘어짐이 나왔습니다. 소매 전환을 넓히고, 바지는 고리 번호 대신 실제 공간 거리로 변형을 분배하여 각각 최대 1.69배 / 1.34배로 줄였습니다. 새 허용 기준은 코트 최대 2배·프레임별 99백분위 1.6배, 바지 최대 2배·99백분위 1.8배입니다. 이전 5배 붕괴 방지 기준과 구분합니다.
- 120프레임 독립 관절 시험에는 어깨 앞뒤 회전, 상완 약 65도 내리기, 팔꿈치 약 65도, 무릎 약 55도 굽힘을 포함했습니다. 고관절 ±25도 시험도 별도로 수행했고 바지 모서리 최대 늘어짐 약 1.47배로 통과했습니다. 모든 뼈 크기는 1을 유지합니다. 쇄골만 ±15도로 회전한 별도 시험에서 어깨 표면의 변위 중앙값 약 40mm를 확인했습니다. 이전 달리기의 2.7mm 측정과는 동작 조건이 달라 직접 배율로 비교하지 않습니다.
- GLB에는 곡면·의상 두께를 적용하여 내보내고, 다시 불러온 세 자세의 범위 오차 약 1.2e-7m를 확인했습니다. Blender가 가져올 때 만드는 뼈 표시용 Icosphere는 모델 검사에서 제외합니다.

새 모델의 독립 관절 시험은 달리기·접지·옷 충돌 검증이 아닙니다. 앞으로 기존 손 경로 고정 보정을 옮기지 않고, 새 기준 자세와 실제 Kimodo 어깨 채널에 맞춰 다시 매핑합니다. 아래 절들은 이전 모델의 보정 경과입니다.

재실행(WSL 저장소 루트):

```sh
BLENDER=/opt/deviant-blender/blender-4.5.13-linux-x64/blender
"$BLENDER" -b --factory-startup --python-exit-code 1 --python scripts/rebuild-hero-model.py
"$BLENDER" -b --factory-startup --python-exit-code 1 --python scripts/verify-hero-model.py
"$BLENDER" -b --factory-startup --python-exit-code 1 --python scripts/verify-hero-model-glb.py
"$BLENDER" -b --factory-startup --python-exit-code 1 --python scripts/render-hero-model.py
/opt/deviant-kimodo/.venv/bin/python scripts/encode-hero-model.py
"$BLENDER" -b --factory-startup --python-exit-code 1 --python scripts/render-hero-model-rig.py
```

출력: `hero-model-front.png`, `hero-model-rig.png`(기준 자세 관절 배치), `hero-model-contact-sheet.png`, `hero-model-deformation-preview.mp4` / `.gif`. 관절 배치 그림의 안내 선은 별도 렌더용이며 편집 모델이나 GLB에 들어가지 않습니다. 검사·실행 기록은 `docs/logs/hero-model-*`입니다.

## 조건과 객관적 검사

카메라는 높이·방향이 고정된 정사영 순수 측면입니다. 캐릭터의 등속 전진량만 임시 씬에서 제거하고 골반의 원래 움직임은 유지했습니다. 바닥은 숨기고 투명 배경으로 렌더링했습니다. 원본 `hero-run.blend`를 저장하거나 덮어쓰지 않습니다.

현재 한 주기는 18프레임·0.6초이며 다섯 주기 90프레임·3초를 렌더링합니다. 91번 프레임은 반복 경계 검사 전용입니다. MP4와 GIF 모두 90프레임·3초입니다. 비교의 이전 구간만 기존 45프레임 루프를 두 번 반복하며, 두 모션을 같은 경과 시간으로 비교합니다. GIF 시간 단위 때문에 30·30·40ms를 반복 배치하여 전체 길이를 유지했습니다.

인코딩·실제 디코딩·프레임 잘림·반복 경계는 수치 검사로 확인하며, 최신 시작/끝 RGBA 평균 차이는 `hero-run-side-check.json`을 참조합니다. 이는 미적 자연스러움이나 옷 충돌 통과를 의미하지 않습니다.

캔버스 크기와 캐릭터 높이는 다릅니다. 최신 실제 캐릭터 높이 범위는 `hero-run-side-check.json`의 `character_pixel_height_ranges`를 참조합니다. 자세와 전경은 바뀌었으나 메시 크기를 바꾼 것이 아닙니다. 축소 비교는 같은 프레임·카메라·색을 사용하며 프레임별 별도 팔레트를 생성하지 않습니다.

## 순서대로 적용한 보정

1. **발목·하체:** 기존 방식은 신발의 바닥 기준 기울기만 제한하고, IK로 바뀐 종아리와 신발의 상대 회전은 제한하지 않았습니다. 기본 자세 대비 발목 회전은 공중 최대 약 85.16도, 접지 중 약 60.82도였습니다. 발목 위치의 앞뒤 경로를 캐릭터에 맞게 줄이고, 접지 구간은 몸 중심 경로 아래에 배치했습니다. 공중 발의 높이는 제약을 만족하도록 함께 계산하고, 골반은 접지 다리의 도달 범위에 맞춰 조정합니다. 다리 길이나 메시 비율은 바꾸지 않습니다.
2. **신발·발목 옷:** 작업용 신발 본체(기본 Z<0.105m)를 단단한 한 영역으로 만들고, 0.105~0.165m 연결 구간에서 신발·종아리 영향을 연속적으로 나눴습니다. 접지에서는 6~18도 정도의 발끝 구름을 사용하며 한 접지 구간에서 동일한 발끝 정점을 축으로 유지합니다. 프레임마다 최저점을 새로 고르면 같은 높이의 다른 정점으로 축이 바뀌어 옆으로 튈 수 있어 이를 제거했습니다. 공중에서는 정강이 기준 관절 회전 40도 안에서 신발 방향·발바닥 높이·고정 길이 다리를 반복 계산합니다. 최종 접지 포함 최대는 약 44.05도입니다. 이 값은 이 캐릭터의 미술 기준이며 인체 해부학 기준이 아닙니다.
3. **팔:** 처음에는 측면 가독성을 위해 손 경로를 넓혔으나, 사용자 피드백에 따라 생성된 박자는 유지하면서 낮고 뒤쪽에 무게를 둔 작은 경로로 바꿨습니다. 좌우 손의 앞뒤 이동 폭은 약 0.192m/0.208m에서 0.101m/0.125m로 줄였고, 몸 중심에서의 가로 간격도 약 0.205m에서 0.18m로 줄였습니다. 가장 높은 손목도 가슴 기준점보다 약 5.3cm 아래에 있습니다. 좌우 이동 배율 0.88/1.0, 높이 차이 7mm의 작은 비대칭을 주고, 팔꿈치는 뒤로 빠지는 안정된 평면을 유지합니다. 손목 중립과 고정 길이 두 뼈 IK는 유지합니다. 팔 관절의 프레임당 최대 회전은 약 9.16도입니다.
4. **후드·몸통:** 기존 상체 방향 안정화를 유지하면서 몸통에 전경 6도를 추가했습니다. 후드와 목이 다시 찢어지지 않도록 머리·가슴의 변형은 계속 일치시킵니다. 상체 좌우 회전을 80% 줄이고 화면 쪽으로 8도 방향 보정을 둔 상태이며, 전경 추가 후 머리 앞 방향 변화 폭은 약 7.89도(-11.89~-4.00도)입니다. 독립적인 시선·고개 리그를 새로 만든 것은 아닙니다. 이전 상체 보정 단계에서는 하체·루트 키를 유지했으며, 최신 단계는 박자와 발바닥 궤적을 함께 보간합니다.
5. **옷과 픽셀 검토:** 작은 팔 경로와 안정된 굽힘 평면을 적용한 뒤 90프레임의 소매 모서리와 중복 표면 틈을 검사했습니다. 최대 소매 모서리 늘어짐은 약 3.93배, 99백분위는 약 2.32배로 심한 폭발 변형의 회귀 기준을 통과했습니다. 이 숫자는 여전히 국소 옷 늘어짐이 있다는 뜻이기도 합니다. 메시를 새로 재토폴로지하지는 않았으며, 작은 눌림·겹침은 최종 미술 정리 대상으로 남습니다.

접지 검사는 실제 접촉면 0.2mm와 지면 근처 3mm 영역을 구분합니다. 빠른 모션의 보간 중 발떼기 자세는 공중으로 올라가면서 3mm 영역을 지나므로, 이 영역 전체의 움직임을 미끄러짐으로 취급하지 않습니다. 전체 영역 평균은 진단값으로 남기고, 원본 접지 분류가 연속으로 유지되는 구간에 0.005m/s 기준을 적용합니다. 최신 접지 구간 평균은 약 0.00153m/s, 공중 발떼기를 포함한 전체 3mm 영역 평균은 약 0.04102m/s입니다. 두 단계 보간과 두 주기 평균에 사용된 원본 프레임을 모두 추적해, 전부 접지로 분류된 구간에만 접지 조건을 적용합니다. 실제 0.2mm 접촉면에도 별도로 같은 0.005m/s 기준을 적용합니다. 지면 관통·뼈 길이·원래 크기·반복 끝·카메라 등속·GLB 왕복은 별도 검사합니다.

## 화면 검토와 남은 범위

- 다리의 앞뒤 교차와 공중 구간으로 달리기 동작은 읽힙니다. 이번 비교에서는 캐릭터 높이 약 75~102픽셀 쪽이 작은 장갑·스카프를 구분하기 수월합니다. 50픽셀 전후에서도 달리기는 보이지만 작은 부분의 계단 변화와 세부 손실이 큽니다.
- 최초 적용본에서는 여러 자세의 손·팔이 몸통에 묻히고 후드 방향 변화로 눈이 보였다 사라졌습니다. 보정본은 손 경로를 넓히고 방향을 안정시킨 상태로 같은 카메라에서 비교합니다. 팔다리가 서로 지나가는 순간의 겹침까지 모두 없애지는 않습니다.
- 소매의 국소 굴곡·겹침은 여전히 남아 있습니다. 작은 해상도가 일부 주름을 숨기더라도 팔과 몸통의 겹침이나 큰 윤곽 변화를 해결해 주지는 않습니다.

현재 결과는 **측면용 동작을 보정한 검토본**입니다. 무기·공격 전환·실시간 지형 IK·모든 옷 충돌은 검증하지 않았습니다. 최종 도트 팔레트·윤곽 정리와 최종 스프라이트 프레임 선정은 별도 작업입니다. 이 단계에서는 원본 형태를 유지한 보정과 같은 크기에서의 비교까지 수행합니다.

## 재실행

WSL 저장소 루트에서:

```sh
/opt/deviant-blender/blender-4.5.13-linux-x64/blender -b --factory-startup --python-exit-code 1 --python scripts/render-hero-side.py > docs/logs/hero-run-side-render.log 2>&1
/opt/deviant-kimodo/.venv/bin/python scripts/encode-hero-side.py > docs/logs/hero-run-side-encode.log 2>&1
```

캐릭터 보정은 먼저 `HERO_MOTION=run`으로 `scripts/rig-hero.py`를 실행하고, `verify-run-motion.py`, `verify-run-upper.py`, `verify-run.py`, `verify-hero.py`, `verify-hero-arms.py`, `review-hero.py`, `test-retarget.py`를 검사합니다. `verify-run-upper.py`는 기준 커밋의 Blend를 로컬 Git에서 캐시로 복구할 수 있습니다. 상체 검사 기준은 새 미술 방향에 맞게 작은 손 경로·낮은 손 위치·뒤쪽 중심을 확인하며, 기존의 큰 이동 폭 하한을 그대로 적용하지 않습니다. 발목·신발·급회전 기준은 유지합니다.

GLB·일반 영상 재생성은 `docs/RUN_RESULT.md`를 참조합니다. `compare-run-motion.py`는 `.cache/hero-run-body-side-before`에 보존한 6d694eb의 측면 45장을 두 번 반복하여 현재 측면 90장과 비교합니다. 다른 컴퓨터에서는 이 기준 커밋을 별도 체크아웃해 측면 PNG를 재생성한 뒤 해당 캐시에 복사합니다. `HERO_COMPARE_FRAMES`와 `HERO_COMPARE_COMMIT`으로 다른 기준을 지정할 수 있습니다. 비교를 위해 현재 작업 파일을 과거 상태로 덮어쓰지 않습니다.

프레임 PNG는 무시되는 `.cache/hero-run-side-frames`에 저장합니다.
