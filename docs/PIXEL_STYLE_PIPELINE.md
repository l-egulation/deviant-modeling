# 3D 캡처에서 팀원 화풍으로: 기준 그림과 제작 절차

2026-10-26. 상태: **정지 기준 시안 제작/기술 규격 검증 완료. 미술 승인 및 여러 자세의 일관성 검증 전.**

## 이번 결과

`outputs/pixel-style-master/comparison.png`: 왼쪽 3D 입력, 가운데 팀원 원본, 오른쪽 기준 시안. 세 그림의 캐릭터 높이는 64px이며 표시 배율은 5배다. 캔버스 높이를 비교한 것이 아니다.

- `master-128.png`: 실제 사용 규격의 투명 PNG. 캐릭터 경계 44×64px, 캔버스128×128, 경계 (42,40)-(86,104).
- `master-preview.png`: 최근접6배 확대.
- `generated.png`: 내장 image_gen이 만든 편집 원본. 팀원 그림을 스타일 기준, pixel-idle-pose.png를 캐릭터/자세 참고로 입력했다.
- `prompt.txt`: 실제 사용한 전체 프롬프트. CLI/API 별도 실행은 하지 않았다.
- `validation.json`: 크기/색/알파와 한계. 원래 AI 결과에는 불투명 RGB 13,093색이 있어 그대로 게임용6색이라고 부를 수 없었다. 기술 출력에서 고정 팔레트·격자로 정리했다.

**3D의 형상/골격/모션 파일은 바꾸지 않았다.** 새 도트는 AI가 팔 자세와 후드/스카프 윤곽을 해석해 다시 그린 후보다. 참고 그림에 더 가까워졌지만 3D 투영을 정확히 보존한 결과는 아니다. 이 한 장으로 임의 모션의 스타일 변환이 해결됐다고 판단하지 않는다.

## 기준 규칙

| 항목 | 기준 |
|---|---|
| 픽셀 밀도 | 중립 캐릭터 전체 높이64 논리px.128은 캔버스 크기다. 이전64격자 전체 캔버스와 구분 |
| 팔레트 | FDEEDA / D2B396 / 1B1616 / 025673 / 02648C / EBA516 |
| 투명도 | 0 또는255. 표시 확대는 정수배 최근접 |
| 기준점 | 이 후보는 발바닥 경계 y=104, 가로 기준64. 모든 프레임 공통 캔버스·기준점·배율 |
| 기본색 | 큰 연결 면을 유지. 얼굴·손·부츠·금색은 단색 |
| 그림자 | 후드 뒤/아래, 먼 소매, 로브 한쪽의 선택된 큰 색면. 작은 법선 변화로 재분류하지 않음 |
| 윤곽 | 후드 끝·얼굴 입구·손·두 부츠·스카프 꼬리를 작은 크기에서 구분 |
| 미세 표현 | 그라디언트/질감/디더링/작은 광택 배제. 눈·장식 이외 의미 없는 점 제거 |
| 금지 | 머리 눌림, 프레임별 비율 재조정, 프레임별 자동크롭 확대, 모든 프레임 독립 AI 재생성 |

이 후보의 눈은 팀원 눈보다 상대적으로 굵고, 얼굴/머리 비율과 팔 자세는 같지 않다. 미술 승인 시 확인할 차이이며 현재 규격 검사가 화풍 승인을 대신하지 않는다.

## 반복 가능한 제작 순서

1. **3D 참고 추출**: 같은 카메라·배율·발 기준점으로 포즈와 로브/스카프 움직임을 추출. 움직임의 근거로 보관한다. 관절 방향/접지와 그림체 문제를 구분한다.
2. **기준 그림 승인**: 이번 한 장을 팀원 그림과 실제 크기/정수 확대에서 비교한다. 큰 형태·눈·그림자 모양을 결정한다. 새 AI 생성은 후보 제안이며 정확한 변환 함수가 아니다.
3. **부위별 편집 기준**: 승인된 그림을 후드/얼굴/몸통/양팔/양다리/스카프로 분리하고 앞뒤 가림 순서를 지정한다. 이 분리는 아직 제작하지 않았다. 색으로만 부위를 구분하면 얼굴과 부츠 등이 섞이므로 의미별 마스크가 필요하다.
4. **주요 자세의 제한 편집**: 대기는4~6자세부터. 3D 관절 위치를 참고하되 해당 부위의 필요한 픽셀만 수정한다. 얼굴·눈·후드 내부 색면은 머리의 방향이 같으면 유지한다. 스카프는 물리 참고에서 읽히는 주요 굽힘만 선택한다. 회전/변형만으로 생기는 픽셀 구멍과 계단은 정리한다.
5. **시간 검토**: 중요하지 않은 색면은 프레임 간 고정. 부위 정렬 후 불필요하게 바뀐 픽셀, 한 프레임만 생기는 그림자/점, 루프 경계를 확인한다. 발 고정 동작에서 접지점이 움직이면 실패. 움직여야 할 천까지 통째로 얼려 일렁임을 숨기지 않는다.
6. **출력**: 선택한 자세의 유지시간을 기록해 GIF/스프라이트 시트로 내보낸다.30fps는 재생 시간축이며 매초30장의 서로 다른 그림을 요구하지 않는다. 게임용 프레임 시간 정보도 함께 전달한다.

3~6단계는 다음 제작/검증 단계다. 한 장의 스타일 제안과 팔레트 정규화만으로 애니메이션 일관성을 보장하지 않는다. 달리기로 확대하기 전에 대기 주요 자세와 서로 다른 달리기 접지/공중 자세3장의 일관성을 확인한다.

## 통과 기준과 재현

현재 자동 검사: 캔버스128×128, 캐릭터 높이64px, 허용6색 이외0, 알파0/255. 미술 검토: 두 부츠 분리, 손과 로브 구분, 단순 그림자/넓은 스카프는 후보에서 읽힌다. 자세 보존/눈 크기/후드 형태는 승인 전이다. 시간적 안정성은 정지 그림이라 미검증이다.

`scripts/export-pixel-style-master.py`는 보관한 생성 원본을 기술 규격으로 내보내고 비교 그림/검증JSON을 재현한다. 스타일을 새 포즈에 자동 적용하는 스크립트가 아니다. 이 스크립트의 경계 크롭/64px 정규화는 **정지 마스터를 최초 정의할 때만** 사용하며 애니메이션 프레임마다 적용하지 않는다.
