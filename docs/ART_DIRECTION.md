# 주인공 도트·3D 제작 기준

확정일: 2026-10-22. 사용자가 팀원 화풍를 기준으로 분석·규칙 결정을 요청했습니다. 긴 청록 스카프와 허벅지 위쪽 로브(앞트임)는 사용자 선택입니다. 아래에서 원본 측정값, 제작 규칙, 아직 검증하지 않은 시작값을 구분합니다.

## 실제 측정

첨부한 팀원 캐릭터 PNG(1024×1024)는 색 경계가 8px 격자에 맞고, 흰 배경을 제외한 경계가 (296,456)-(680,968)입니다. 따라서 원래 그림의 경계는 48×64 논리 픽셀입니다. 제공된 채찍 대기 GIF 첫 프레임도 3배 확대된 51×64 논리 픽셀이며 동일한 6색을 사용합니다. GIF의 경계에는 작은 무기/바닥 형태가 포함되어 디자인 크기는 첨부 PNG를 우선합니다.

| 역할 | 고정 색상 |
|---|---|
| 아이보리 기본색 | #FDEEDA |
| 아이보리 그림자 | #D2B396 |
| 얼굴·장갑·부츠 | #1B1616 |
| 청록 기본색 | #025673 |
| 청록 강조색 | #02648C |
| 눈·장식·발목 금색 | #EBA516 |

배경/투명은 위 색 수에 포함하지 않습니다. 금색 눈 두 덩어리는 각각 2×5 논리 픽셀입니다. 얼굴의 검정 연결 영역은 약 17×16 픽셀 경계입니다. 이는 정지 참고 자세의 측정값이며 모든 방향·자세에 같은 사각형을 붙인다는 뜻은 아닙니다. measurements.json과 native-shapes.json에 측정 결과를 보관합니다.

## 고정할 제작 규칙

- 팀원 첨부 PNG의 외형을 디자인 기준으로 삼습니다. PixelLab 생성본은 후보 이력이며 새로운 디자인 정답으로 사용하지 않습니다.
- 주인공의 중립 자세 높이는 64 논리 픽셀을 기준으로 합니다. 96×96 투명 캔버스, 발 기준점 (48,80)을 첫 규격으로 사용합니다. 공격·긴 무기에는 같은 픽셀 밀도로 더 큰 캔버스를 쓰며, 전신 높이를 임의로 축소해 맞추지 않습니다. 다른 크기의 적은 같은 화면의 픽셀 밀도로 설계합니다.
- 위 6색만 사용하는 주인공 출력. 얼굴·장갑·부츠·금색은 단색, 아이보리는 기본/그림자 2단계, 청록은 기본/강조 2색입니다. 색 보정·조명으로 새 중간색을 만들지 않습니다. 적은 이 팔레트를 바탕으로 필요한 재질 색을 별도 지정하며 주인공의 6색을 모든 적에 강요하지 않습니다.
- 최종 이미지는 정수 배율/최근접 확대. 그라디언트, 천 결, 해칭, 반짝이는 재질, 디더링, 부드러운 가장자리와 반투명 경계를 배제합니다. 스프라이트 알파는 0/255 두 값으로 검사합니다.
- 검은 외곽선을 일괄 추가하지 않습니다. 큰 기본색 면과 선택한 그림자 덩어리로 부피를 표현합니다. 자동 조명을 단순 색상 축소만으로 대체하지 않고 재질별 색/명암을 고정합니다.
- 최종 해상도에서 의미 없는 지퍼 이빨·바느질·작은 주름·잉크 가닥은 제거/통합합니다. 눈처럼 의미 있는 세부와 달리, 부수적인 천 끈/가닥은 최소 2px 정도로 읽히게 정리합니다.
- 원본은 실제 Tripo A 모델 outputs/hero-proportion-model.glb이며, 검토 모션은 hero-mixamo-run.blend입니다. 현재 리그와 모션을 우선 재사용합니다. 이전에 거절된 절차적 캐릭터로 교체하지 않습니다.

## 디자인 결정

- 큰 후드·검은 얼굴·금색 세로 눈·아이보리 의상·청록색·검은 장갑/신발을 유지합니다.
- 후드는 둥근 구형 대신 팀원 그림의 뒤로 빠지는 끝과 얼굴 테두리를 목표로 부분 수정합니다. 64px 출력에서 두 눈과 얼굴 입구가 읽혀야 합니다.
- 스카프: 사용자 선택으로 긴 형태 채택. 목을 두른 고정부와 넓게 읽히는 천 꼬리를 구분합니다. PixelLab 후보의 여러 가느다란 리본은 채택하지 않습니다. 팀원 그림처럼 하나의 넓은 천이 갈라진 끝을 가진 실루엣을 우선합니다. 정확한 끝 모양은 실제 한 장 렌더에서 확인합니다.
- 로브: 사용자 선택으로 허벅지 위쪽 길이, 앞트임 유지. 어깨/소매/상체는 리깅으로 움직이고, 밑단은 별도 변형 영역으로 만듭니다. 앞트임으로 양다리의 앞뒤 교대가 보여야 합니다.
- 카메라 시작값: 직교 투영, 완전 측면에서 정면 쪽으로 30도, 약한 하향 5도. 두 눈과 실루엣을 보고 30~45도 사이에서 최종 각도를 결정합니다. 이 수치는 렌더 검증 전 시작값입니다. 방향/배율/높이를 정한 후 프레임마다 바꾸지 않습니다.

## 천 물리 요구사항

스카프와 로브가 몸에 붙어서 회전만 하거나 임의로 사인파 흔들림을 반복하는 것으로 완료 처리하지 않습니다.

- 스카프 목 부분 고정, 천 꼬리는 관성·중력·몸의 가속/감속과 상대 공기 흐름에 반응하도록 계산합니다. 머리·목·몸통·팔 충돌을 검사합니다. 달리기가 멈추거나 방향이 바뀔 때 지연/오버슈트가 읽혀야 합니다.
- 로브 상체/소매는 골격 가중치, 옷자락은 천 물리 또는 물리 기반 보조 골격으로 분리합니다. 밑단이 골반/다리/발을 뚫거나 끼이는 문제를 검사합니다. 바지와 로브를 한 좌표 범위 가중치로 뭉뚱그려 연결하지 않습니다.
- 우선 스프라이트 제작용 오프라인 계산/베이크입니다. 게임 엔진의 실시간 천 물리를 이미 구현했다는 뜻이 아닙니다.
- 정지 안정화 → 일정 속도 달리기 → 급정지 → 좌우 전환의 시험을 따로 수행합니다. 관성과 천의 지연을 확인합니다. 과한 펄럭임 때문에 얼굴·발·무기가 가려지지 않아야 합니다.
- 실제 이동 좌표에서 시뮬레이션하거나, 제자리 동작이라면 상대 바람/가속 조건을 명시합니다. 화면에서 제자리 달리기로 보인다는 이유로 물리상 이동/공기 흐름이 사라지지 않게 합니다.
- 사전 안정화 후 구간을 베이크하며, 동일 캐시에서 동일 결과를 재생합니다. 30fps 출력에 충분한 계산 세분화를 설정하고 충돌/잔떨림을 보고 조절합니다. 아직 특정 설정을 통과했다고 주장하지 않습니다.
- 반복 경계의 위치/속도 불연속과 픽셀 점프를 확인합니다. 천의 긴 주기가 달리기 한 주기와 맞지 않으면 여러 주기의 반복을 사용하거나 경계를 보정한 뒤 충돌을 재검사합니다. 마지막 프레임을 첫 프레임에 단순 강제 복사해 해결하지 않습니다.

## 실행 순서와 통과 기준

1. 팔레트/픽셀 격자 확정: 이번 분석에서 완료. team-native.png와 reference-and-palette.png가 근거입니다.
2. 기존 A 모델의 한 자세에 6색 재질·고정 명암·사선 카메라 적용. 2026-10-22 시험 완료. docs/ART_PROTOTYPE.md 참조. 색/알파 검사는 통과했으나 형태 일치는 미통과입니다.
3. 팀원 그림과 같은 크기에서 비교해 후드·얼굴 입구·로브·스카프 형상을 부분 수정합니다. 전체 모델 재제작부터 시작하지 않습니다.
4. 정지 상태에서 천을 연결하고 관절/충돌 시험. 외형 통과와 물리 통과를 별도로 기록합니다.
5. 서로 다른 세 달리기 자세에서 얼굴/비율/팔레트·발 기준점·옷 변형 검사.
6. 물리 베이크와 반복 경계 검사 후 전체 30fps 스프라이트 추출.

색 6개/알파 2값/공통 캔버스·기준점은 자동 검사합니다. 팀원 그림과의 형태 일치, 천의 자연스러운 관성, 잔떨림과 가림 여부는 확대 정지 화면과 실제 재생을 함께 봅니다. 물리가 움직인다는 사실만으로 품질 통과로 간주하지 않습니다.
